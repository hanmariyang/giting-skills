### 01 · ui-menu — UI 메뉴판

"접었다 폈다 되는 거"를 **아코디언**이라 부르게 해 주는 사전입니다. 이름을 아는 순간 AI에게 시키는 시간이 줄어듭니다.

- **11개 코스 131개 항목**: ①페이지 뼈대 ②이동·탐색 ③내용 보여주기 ④입력받는 것 ⑤누르는 것 ⑥알려주는 것 ⑦작은 표시들 ⑧상태·동작 ⑨스크롤 연출 ⑩마우스 반응 ⑪불러오기·흐름
- **별칭 사전**: 사람이 실제로 하는 말("화면 가운데 뜨는 창", "옆에서 미끄러져 나오는 메뉴") → 정식 명칭 매핑
- **AI한테 시키는 공식**: [어디에] + [컴포넌트 이름] + [개수] + [세부 조건] — 항목마다 그대로 복사해 쓰는 요청 문장
- **실물 HTML**: 전 항목이 그림이 아니라 실제로 동작하는 자가완결 HTML (의존성 0, 접근성 기본 포함)
- **에이전트 채널**: [llms.txt](https://giting.kr/skills/llms.txt) · [llms-full.txt](https://giting.kr/skills/llms-full.txt) (코드 포함)

라이브 갤러리: **https://giting.kr/skills/**

설치하면 Claude가 네 가지를 합니다.

1. **통역** — "위에 눌러서 화면 바뀌는 거" → "그건 탭(Tabs)입니다" + 다음부터 쓸 요청 문장
2. **요청 다듬기** — 두루뭉술한 요청을 공식대로 다시 써서 확인
3. **구현** — 검증된 레퍼런스 HTML을 기반으로 기존 코드 스타일에 맞춰 이식
4. **제안** — "이 목록이 너무 길어" → 상황에 맞는 컴포넌트를 근거와 함께 추천

### 02 · css-menu — CSS 증상 사전

깨진 화면을 CSS 용어가 아니라 **증상**으로 찾는 사전입니다. "가운데 정렬이 안 돼요", "스크롤이 두 개예요", "버튼이 안 눌려요"를 그대로 입구로 씁니다. 기획자·디자이너 등 비개발자 우선 설계.

- **8개 코스 42개 항목**: ①정렬 ②삐져나옴·잘림 ③스크롤 ④겹침·가려짐 ⑤폰에서만 ⑥간격 ⑦글자 ⑧안 보임
- **깨진/고친 실물 나란히**: 전 항목이 before/after 실제 동작 HTML — 이중 스크롤은 굴려보고, 막힌 버튼은 눌러본다
- **즉방형 34 · 분기형 8**: 상황 불문 같은 처방인 것만 "고쳐줘" 문장을 주고, 상황 의존(한글 줄바꿈·줄 간격 등)은 **진단 먼저** — 일률 처방으로 위장하지 않는 것이 검수 기준
- **확인법 동봉**: 항목마다 "고쳐졌는지 눈으로 확인하는 방법" ("창 높이를 바꿔도 가운데면 성공")
- **에이전트 채널**: [llms.txt](https://giting.kr/skills/css-menu/llms.txt) · [llms-full.txt](https://giting.kr/skills/css-menu/llms-full.txt)

라이브 갤러리: **https://giting.kr/skills/css-menu**

### 04 · type-menu — 타입스크립트 에러 사전

영어에 코드번호로 뜨는 TS 에러(TS18048·TS7006·TS2322…)를 사람 말로 옮기고, any로 덮지 않고 제대로 고치는 사전.

- **6개 코스 15개 항목**: undefined·null / 암묵 any / 타입 불일치 / 속성·모양 / 좁히기·유니온 / async·Promise
- **실제 tsc 원문 + before/after**: 전부 실제 컴파일러가 뱉은 에러 메시지 기준
- **any·! 로 덮지 않음**: 좁히기(가드·옵셔널·기본값·타입 정정)로 진짜 안전하게. 상황 의존은 분기형으로 진단 먼저

라이브: **https://giting.kr/skills/type-menu**

### 05 · font-menu — 웹폰트 사전

"폰트 예쁘게 넣어줘"라고 하면 AI는 늘 쓰던 Inter만 얹거나, Google Fonts에 없는 폰트(Satoshi·General Sans)를 Google 링크에 박아 조용히 시스템 폰트로 폴백시킨다. 인상으로 폰트를 고르고, 어디서 어떻게 불러오는지 로딩 스니펫째 주는 사전.

- **7개 맥락 34종**: 국룰·본문 / AI·테크 / 랜딩 히어로 / 고급·세리프 / 코드·모노 / 한글 / 한글 제목·손글씨
- **짝 12개**: 한글+한글 · 한글+영문 · 영문+영문. 제목 글꼴과 보조 글꼴, 둘의 차이를 두는 규칙, 견본 문장, AI에게 할 말. 공통 규칙은 「한 화면에 한글 글꼴은 두 개까지, 나머지 차이는 굵기와 크기로」
- **로더가 폰트마다 다르다**: Google Fonts(번들 자유) · Fontshare(CDN 로드만, 번들 금지) · jsDelivr(Pretendard 등). 출처별 정확한 `<link>`를 준다
- **로드 실측**: 처음 24종은 로드 URL을 전부 GET 해 @font-face·패밀리명이 실제로 오는지 확인했고(silent fallback 0), 2026-10-23에 넣은 한글 제목·손글씨 10종은 헤드리스 Chrome에서 스니펫만 넣은 페이지로 글꼴이 실제로 붙는지 확인했다. 짝·라이선스·안 쓸 때·AI 티 경고 포함

라이브: **https://giting.kr/skills/font-menu**

### 06 · app-menu — 앱 UI 메뉴판

ui-menu의 **모바일판**. "아래에서 올라오는 판"을 **바텀시트**, "앱 켜면 뜨는 로고 화면"을 **스플래시**라 부르게 해 주고, 그 이름을 SwiftUI·Flutter·React Native의 실제 컴포넌트명까지 연결하는 사전.

- **8개 코스 73개 항목**: ①화면 뼈대 ②화면 이동 ③목록 ④입력받는 것 ⑤골라 넣는 것 ⑥누르는 것 ⑦위에 띄우는 것 ⑧상태·표시
- **네이티브 매핑 38항목**: 정식 명칭 → SwiftUI · Flutter · React Native 실제 컴포넌트명(탭바 → TabView·BottomNavigationBar·Tab.Navigator)

- **웹 UI는 ui-menu**: 이 사전은 iOS·안드로이드 앱 전용

### 13 · flow-menu — 흐름 메뉴판

「결제 화면 만들어줘」를 **장 단위 계획으로** 바꿔 주는 사전. 고객이 한 가지 일을 끝내기까지 넘기는 화면을 장마다 이름 붙이고, 장마다 쓰는 부품을 app-menu 이름 그대로 적는다.

- **흐름 셋**: 결제 5장(배송지 · 할인 · 결제 수단 · 확인·동의 · 완료) · 가입 5장(가입 방법 · 닉네임 · 동네 · 관심사 · 권한) · 예약 5장(시간 · 장소 · 고르기 · 옵션 · 확인·결제). 실제 앱 화면에서 순서와 부품을 확인
- 장마다 한 줄 요점 · 부품 셋 · 요청 문장, 그리고 **장을 넘겨도 지킬 것**(결제 버튼은 ①~④ 금액을 달고 하단 고정 바에)
- 견본은 다섯 화면을 나란히 놓은 자가완결 HTML, 부품마다 `data-menu`. 갤러리 **https://giting.kr/skills/flow-menu**
- **실측**: 이름 없이 시키면 금액 단 결제 버튼을 ①~④ 하단에 둔 것 0/6 → 결제 요청 문장으로 5/6, 「주소 찾기」 0/6 → 6/6. 카드사 칸은 4/6. 가입은 이름 없이 시키면 Sonnet 이 3번 다 12장으로 쪼갰고, 가입 문장으로 다섯 장 5/6. 예약은 이름 없이 6번 다 장소부터 물었고, 예약 문장으로 시간부터 6/6

```
/plugin install flow-menu@giting
```
