# UI 메뉴판 (ui-menu)

사용자가 말하는 모호한 UI 표현을 정식 명칭으로 통역하고, 검증된 실물 HTML로 구현을 돕는 사전이다.

## 데이터 위치 (이 스킬의 플러그인 루트 기준)

- `menu.json` — 사전 SSOT. 항목마다: `id` · `name`(ko/en) · `aliases`(사람이 실제로 하는 말) · `oneliner`(한 줄 정의) · `ask`(그대로 쓸 수 있는 요청 문장) · `category`
- `components/<id>.html` — 항목별 레퍼런스 구현. 전부 자가완결 단일 파일(의존성 0), 접근성 기본 포함

이 SKILL.md 는 `skills/ui-menu/` 에 있으므로, 플러그인 루트는 두 단계 위다. 먼저 `menu.json` 을 읽어라.

## 사용법 3가지

**1. 통역 — 사용자가 UI를 말로 설명할 때**

"위에 눌러서 화면 바뀌는 거" 같은 표현이 오면 `menu.json` 의 `aliases` 와 대조해 항목을 찾는다. 답은 이 형태로:

> 그건 **탭(Tabs)** 입니다. 버튼을 눌러 같은 자리의 내용을 갈아 끼우는 전환 장치예요.
> 다음부터는 이렇게 요청하면 됩니다: "월간·연간 두 개 탭으로 요금표가 전환되게 해줘."

`aliases` 에 정확히 없어도 뜻이 통하면 가장 가까운 항목으로 답한다. 두 개가 헷갈리는 표현(예: "팝업" 은 모달일 수도 토스트일 수도)이면 차이를 한 줄로 비교해 고르게 한다.

**2. 구현 — 해당 컴포넌트를 만들어 달라고 할 때**

`components/<id>.html` 을 읽고 그 구조를 레퍼런스로 삼는다. 그대로 복붙이 아니라, 사용자의 기존 코드 스타일·디자인 토큰에 맞춰 이식한다. 단, 레퍼런스가 지키는 것들은 유지한다:

- 시맨틱 요소 우선 (`<dialog>` 로 모달·드로어, `<details name>` 으로 아코디언, checkbox 로 스위치)
- 접근성 최소선 (aria-current, aria-expanded, role, focus-visible, prefers-reduced-motion)
- 의존성 없이 되는 것에 라이브러리를 끌어오지 않는다

**3. 제안 — 무엇을 써야 할지 모를 때**

"이 목록이 너무 길어" → 페이지네이션·탭·아코디언 중 상황에 맞는 것을 `oneliner` 근거와 함께 2개 이내로 제안한다. 나열하지 말고 고른 이유를 말한다.

## 규칙

- 이름을 알려줄 때는 반드시 한국어·영어 이름을 함께 준다. 사용자가 다른 도구·다른 AI에게도 그 이름을 쓸 수 있게 하는 것이 이 스킬의 목적이다.
- `ask` 문장은 그대로 복사해 쓸 수 있는 형태로 보여준다.
- menu.json 에 없는 컴포넌트(예: 스텝퍼, 바텀시트)를 물으면 아는 대로 답하되, 사전에 없는 항목임을 밝힌다.
