# 앱 UI 메뉴판 (app-menu)

모바일 앱 UI는 이름을 알면 플랫폼 관례가 따라온다. "아래에서 올라오는 판"이 **바텀시트**인 걸 아는 순간, 손잡이·높이 단계·바깥 탭 닫기가 같이 온다. 이 사전은 그 말을 정식 명칭으로 옮기고, **SwiftUI·Flutter·React Native의 실제 컴포넌트명**까지 연결한다.

> ⚠️ 이건 **모바일 앱** 사전이다. 웹 UI(헤더·드롭다운·모달 가운데창 등)는 **ui-menu** 를 쓴다. 같은 단어라도 앱과 웹의 관례가 다르다(예: 모달 = 웹은 가운데 작은 창, 앱은 아래서 올라오는 전체 화면).

## 사전을 읽는 법

`menu.json` 이 SSOT다. 8개 코스(화면 뼈대·이동·목록·입력·고르기·버튼·오버레이·상태) 72항목. 항목마다:

- `name` — 정식 명칭 (한글 · 영어)
- `aliases` — 사용자가 실제로 하는 말 ("아래에서 반쯤 올라오는 판")
- `oneliner` — 한 줄 정의
- `ask` — 사용자가 그대로 복사해 쓰는 요청 문장 (플랫폼 관례 포함)
- `vs` — 헷갈리는 것과의 구분 (있을 때)
- `native` — SwiftUI · Flutter · React Native 실제 컴포넌트명 (있을 때)

## 모드 1 — 이름 찾아 주기

사용자가 UI를 말로 풀어 설명하면:

1. `aliases` 와 `oneliner` 로 해당 항목을 찾는다
2. 정식 명칭을 알려 준다 ("그건 **바텀시트**예요")
3. `ask` 문장으로 어떻게 요청하면 되는지 보여 준다
4. 프레임워크를 쓰는 중이면 `native` 로 실제 컴포넌트명까지 짚는다

## 모드 2 — 만들 때 빠짐 점검

앱 화면을 만들거나 고칠 때, 이 사전을 **체크리스트**로 쓴다. 코드는 사람(또는 AI)이 짜되, 무심코 빠뜨리는 모바일 관례를 짚는다. 특히 아래는 자주 빠진다:

- **세이프 에어리어** — 하단 버튼이 홈 인디케이터에 가리지 않게 (`safearea`)
- **탭 타깃 44pt** — 아이콘 버튼이 손가락보다 작지 않게, px 아니라 pt/dp (`taptarget`)
- **엠프티 스테이트** — 목록이 비었을 때 흰 화면이 아니라 안내를 (`emptystate`)
- **로딩 버튼 잠금** — 제출 중 다시 못 누르게, 중복 요청 방지 (`loadingbtn`)
- **모달 = 풀스크린** — 앱의 모달은 아래서 올라오는 전체 화면이 관례 (`modal`)

## 모드 3 — 웹/앱 경계 안내

사용자가 웹 관례를 앱에 그대로 요청하면(드롭다운·가운데 팝업·호버 등) 앱 관례로 바꿔 제안한다: 드롭다운 → 시트로 열기(`selectsheet`), 호버 → 길게 누르기(`tooltip`), 가운데 모달 → 바텀시트/풀스크린.

## 대원칙

- **이름만 대면 관례가 따라온다.** 정식 명칭을 먼저 알려 주고, 그다음 요청 문장을 준다.
- **플랫폼을 존중한다.** iOS·안드로이드·프레임워크마다 컴포넌트명이 다르다. `native` 를 짚어 실제로 쓸 수 있게 한다.
- **생성기가 아니다.** 이 사전은 이름·요청 문장·빠짐 점검을 준다. 코드는 사람이 짠다.

## 금지

- 웹 UI 요청에 이 사전을 쓰지 않는다(그건 ui-menu).
- `menu.json` 에 없는 컴포넌트를 지어내 정식 명칭인 척하지 않는다. 모르면 모른다고 한다.
- 플랫폼 관례를 무시한 채 웹 패턴을 앱에 그대로 심지 않는다.
