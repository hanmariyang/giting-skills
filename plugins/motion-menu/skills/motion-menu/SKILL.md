# 모션 메뉴판 (motion-menu)

사용자가 말하는 모호한 모션 표현을 정식 명칭으로 통역하고, 바로 쓰는 요청 문장과 움직이는 실물 데모로 구현/프롬프트를 돕는 사전이다. 3개 코스 23개 항목.

## 데이터 위치 (이 스킬의 플러그인 루트 기준)

- `menu.json` — 사전 SSOT. 카테고리 3개(①카메라 기본 ②강조·전환 ③타이밍)와 항목마다: `id` · `name`(ko/en) · `aliases`(사람이 실제로 하는 말) · `oneliner`(뜻) · `ask`(그대로 쓰는 요청 문장) · `vs`(헷갈리는 쌍 구분 기준). 일부 항목은 `star`(현장에서 특히 많이 쓰는 것). 상단 `formula`에 모션을 시키는 공식이, `recipes`에 자주 쓰는 모션 조합(오프너·전환·히어로)이 있다.
- `components/<id>.html` — 항목별 **움직이는** 데모 23종. 전부 자가완결 단일 파일(의존성 0), 루프 재생, `prefers-reduced-motion` 존중.

이 SKILL.md 는 `skills/motion-menu/` 에 있으므로 플러그인 루트는 두 단계 위다. 먼저 `menu.json` 을 읽어라. 필요한 항목만 골라 읽어도 된다(카테고리·id 로 검색).

## 중요 — 이건 웹 모션이 아니라 영상·카메라 모션 사전이다

용어의 출처는 촬영·영상 현장이다(팬·틸트·달리·줌·오빗 등). 그래서 **AI 영상 생성 프롬프트**에 그대로 쓰는 게 1순위 용도다. `components/`의 데모는 그 움직임을 브라우저에서 눈으로 보여주려고 CSS 로 재현한 것이지, "이 CSS 를 쓰라"는 뜻이 아니다. CSS 애니메이션에도 응용되지만(이징·스태거·오버슈트·패럴랙스 등), 원래 맥락은 영상이다.

## 사용법 4가지

**1. 통역 — 사용자가 움직임을 말로 설명할 때**

"배경만 빨려 들어가게 해줘" 같은 표현이 오면 `aliases` 와 대조해 항목을 찾는다. 답은 이 형태로:

> 그건 **줌 아웃 트랙 인(Dolly Zoom)** 입니다. 인물 크기는 그대로, 배경만 변하는 현기증 효과예요.
> 다음부터는 이렇게 요청하면 됩니다: "인물 크기는 그대로 두고 배경만 멀어지게 줌 아웃 트랙 인 해줘. 2초."

**2. 구분 — 헷갈리는 쌍이면 `vs` 를 인용**

두 항목에 걸치는 말이 오면 `vs` 기준으로 차이를 먼저 보여주고 고르게 한다.
- "옆으로 움직여줘" → 제자리서 돌면 **팬**, 몸이 옆으로 가면 **트랙**
- "확대해줘" → 렌즈만 당기면 **줌**(배경 그대로), 몸이 다가가면 **달리**(배경 변함)
- "확 당겨줘" → 몇 프레임이면 **스냅 줌**, 0프레임(컷)이면 **펀치 인**
- "튕기게" → 끝나고 지나쳤다 오면 **오버슈트**, 시작 전 반대로 빼면 **안티시페이션**

**3. 요청 문장 — `ask` 를 그대로**

모션은 이름만으로 부족하다. `formula`([어디에] + [모션 이름] + [방향] + [시간/프레임])대로, 각 항목의 `ask` 에 방향·시간이 이미 들어 있으니 그대로 복사해 쓰게 한다.

**4. 조합 — `recipes` 로 한 샷 전체**

"오프너 만들어줘" 처럼 샷 단위 요청이면 `recipes`(제품 소개 오프너·장면 전환·깊이감 히어로)의 `combo` + `ask` 를 쓴다.

## 원칙

- 수치·용어는 `menu.json` 이 정본이다. 지어내지 않는다.
- 데모는 참고용 재현이다. AI 영상 생성이 목적이면 `ask` 문장을, CSS 가 목적이면 데모를 응용한다.
- 모션은 **이름 + 방향 + 시간**. "멋지게/역동적으로"는 매번 다르게 나온다.
