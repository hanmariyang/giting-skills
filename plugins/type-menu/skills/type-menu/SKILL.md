# 타입스크립트 에러 사전 (type-menu)

TS 에러는 영어에 코드번호(TS18048…)라 초보에겐 암호다. 이 사전은 그 메시지를 사람 말로 옮기고, **any 로 덮지 않고 제대로 고치는** 처방을 준다.

## 대원칙 — any 와 ! 로 덮지 않는다

타입 에러를 없애는 가장 쉬운 길은 `any` 캐스팅이나 non-null `!` 다. 하지만 그건 에러를 숨길 뿐 런타임 버그를 남긴다. 이 사전의 기본 방향은 **좁히기(narrowing)** 다 — 가드, 옵셔널 체이닝, 기본값, 타입 정정으로 진짜 안전하게 만든다.

## 사전을 읽는 법

`menu.json` 이 SSOT다. 항목마다:

- `name` — 증상 (사용자가 보는 에러/현상)
- `code` — TS 코드번호 (TS18048 등)
- `aliases` — 같은 에러의 다른 표현
- `culprit` — 무엇이 원인인가
- `kind` — **direct(즉방형)** 또는 **branch(분기형)**
- `rx` (즉방형) 또는 `branches` (분기형)
- `ask` — 사용자가 복사해 쓰는 요청 문장
- `check` — 제대로 고쳐졌는지 확인법
- `err` — 실제 tsc 원문 · `before`/`after` — 에러 코드와 고친 코드

## 유형 규율 — 즉방형과 분기형

**즉방형(direct)**: 고치는 방향이 정해진 에러(undefined 좁히기, 타입 명시, 유니온 typeof 좁히기). 바로 처방한다.

**분기형(branch)**: 상황에 따라 답이 갈리는 것. non-null `!`(정말 안전한가 vs 덮은 건가), 리터럴 타입(고정 상수 vs 런타임 변수), floating promise(기다려야 하나 vs fire-and-forget). **무조건 한 답을 강요하지 않고** 갈림길로 진단부터 시킨다.

## 모드 1 — 에러 통역

사용자가 TS 에러를 붙여넣으면:

1. `code` 와 `aliases` 로 해당 항목을 찾는다
2. 에러를 **사람 말로** 옮긴다 ("이건 이 값이 없을 수도 있다는 뜻이에요")
3. 즉방형이면 처방을, 분기형이면 갈림길 질문을 준다

## 모드 2 — 코드 진단·수정

코드에 접근할 수 있으면 `culprit` 를 단서로 원인을 찾고, `before`/`after` 패턴으로 고친다. **any·! 로 덮지 않는다.**

## 모드 3 — 확인 코치

고친 뒤 `check` 를 사용자 언어로 전한다. "빨간 줄이 사라지고, undefined일 때도 앱이 안 터지면 성공" 까지가 완료다.

## 금지

- 에러를 `any` 캐스팅이나 무근거 `!` 로 덮지 않는다 (분기형에서 안전이 실제로 보장될 때만 `!` 허용)
- 분기형 항목에서 진단 없이 한 답을 강요하지 않는다
- 타입 정의를 고쳐야 할 걸 값 쪽에서 억지로 맞추지 않는다 (뭐가 맞는지 먼저 판단)
